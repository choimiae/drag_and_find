# 실시간 조회 사용량 설계

## 목표

관리자 화면에서 선택한 기간(오늘, 최근 7일, 최근 30일)의 조회 완료, 조회 실패, 조회에 사용된 설치 수를 조회 후 약 15초 안에 확인한다. 웹스토어 전체 설치 수와 기존 GA4 보고서는 별도 지연 통계로 표시한다. 실시간 통계는 D1 연결 이후에 받은 이벤트부터 시작하며 GA4 과거 데이터를 소급하지 않는다.

## 데이터 흐름

기존 확장이 보내는 `POST /telemetry`의 `{ clientId, event, version }` 형식과 최대 50자 조회 제한은 유지한다. 조회 Worker는 기존 입력·요청 빈도 검사 뒤 D1에 한국 시간 기준 일별 완료·실패 건수를 원자적으로 더한다. `clientId`는 SHA-256 해시로 바꿔 일별 고유 사용 설치 수 계산에만 저장하고, 검색어·PDF 내용·URL·원본 ID는 D1에 저장하지 않는다. 기존 GA4 전송도 유지한다. D1과 GA4 중 한쪽이 실패해도 다른 쪽 기록을 시도하고, 전송 실패는 사용자 단어 조회 결과에 영향을 주지 않는다.

D1에는 일별 건수 테이블과 `(날짜, 해시된 설치 ID)` 중복 방지 테이블을 둔다. 완료와 실패를 모두 조회 사용으로 본다. 30일이 지난 고유 설치 기록은 일일 예약 작업에서 삭제한다. 공개 `/telemetry`는 기존 IP 제한을 유지하므로 통계는 운영 참고용이며 과금 기준으로 쓰지 않는다.

## 관리자 화면

조회 Worker와 관리자 Worker는 같은 D1 데이터베이스에 바인딩한다. 관리자 API는 기존 Access 인증 뒤 기간별 D1 건수와 고유 설치 수를 읽는다. 기본 대시보드는 D1 실시간 사용량과 기존 GA4·웹스토어·Worker 상태를 각각 반환한다. 별도의 가벼운 API는 D1 사용량만 반환하고, 화면이 보일 때 15초마다 이를 다시 읽는다. 수동 새로고침도 유지한다. D1이 연결되지 않거나 조회가 실패하면 숫자 0 대신 연결 필요 또는 오류를 표시한다.

요약 카드와 일별 조회 그래프는 D1 수치를 사용하고 출처를 `실시간 · D1`으로 표시한다. 상세에는 D1 실시간 사용량과 기존 `GA4 · 지연 통계`를 분리한다. 웹스토어 전체 설치 수는 기존 일별 통계로 유지하고 `실시간`이라고 표시하지 않는다.

## 검증과 배포

일별 증가·동시 조회·고유 설치 중복 제거·기간 집계·오류 분리·관리자 접근 제한·15초 갱신을 테스트한다. D1을 생성하고 스키마를 적용한 뒤 두 Worker에 같은 DB를 연결한다. 배포 후 실제 조회 한 건을 수행해 D1과 관리자 화면 증가를 확인한다. 확장 패키지와 웹스토어 심사 중인 제출물은 변경하지 않는다. 개인정보 처리방침과 관리자 운영 문서는 새로운 D1 저장을 반영한다.
