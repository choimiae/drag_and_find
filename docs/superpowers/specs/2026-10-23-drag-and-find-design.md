# Drag and Find — 설계 문서

- 작성일: 2026-10-23
- 상태: 사용자 검토 대기
- 경로: Superpowers brainstorming → architectural

## 1. 목적

블로그나 기사를 읽다가 모르는 단어가 나올 때마다 새 탭을 열어 검색하는 번거로움을 없앤다.
단어를 드래그하고 아이콘을 누르거나 단축키를 누르면, **읽던 페이지를 벗어나지 않고** 그 자리에서 뜻을 확인한다.

- 1차 사용자: 개발자 본인. 단, 크롬 웹스토어에 공개할 수 있는 구조로 만든다.
- 성공 기준: 모르는 단어를 드래그하고 한 번 클릭(또는 단축키)하면 몇 초 안에 페이지 위 카드에서 뜻을 보고, 부족하면 구글·네이버 검색으로 한 번에 넘어갈 수 있다.

## 2. 범위

### 포함
- 크롬 확장 프로그램 (Manifest V3)
- 선택 텍스트 옆 🔍 아이콘, 단축키(`Alt+Shift+F`, Mac `⌥⇧F`)
- 한국어 위키백과 요약을 선택 텍스트 아래 카드로 표시
- 카드 하단 구글·네이버 검색 버튼 (선택 문구를 넣은 검색 URL을 새 탭으로 열기)
- 설정: 🔍 아이콘 켜기·끄기, 단축키 안내

### 제외 (이번 범위 아님)
- AI 요약 (외부 AI 서비스, 크롬 내장 AI — 한국어 미지원)
- 네이버 검색 API (사용자마다 키 발급 필요 → 진입 장벽)
- 중계 서버
- 영어 위키백과 등 다른 출처
- 시각 디자인 확정 (구현 전에 시안으로 별도 결정)

### 검토 후 버린 대안 (기록용)
| 대안 | 버린 이유 |
|---|---|
| 크롬 내장 AI(Gemini Nano) 요약 | 한국어 미지원, 높은 PC 사양 요구 |
| 네이버 검색 API (사용자 키) | 공개 시 사용자마다 개발자센터 가입·키 발급 필요 |
| 개발자 키를 확장에 포함 | 키 노출, 전 사용자가 한도 공유 |
| 검색 결과 페이지 스크래핑 | 깨지기 쉬움, 구글 차단, 약관 위반 |
| 구글 Custom Search API | 신규 가입 중단, 2027-01-01 전체 웹 검색 종료 |

## 3. 기술 구성

- 언어: TypeScript
- 확장 개발 도구: WXT (Vite 기반)
- 화면: 프레임워크 없이 DOM 직접 구성 (카드 1개, 설정 화면 1개 규모)
- 테스트: Vitest (단위), Playwright (확장 설치 상태의 실제 크롬 E2E)
- 패키지 매니저: pnpm

## 4. 구조

```
① 페이지 쪽 (content script)  ── 메시지 ──  ② 백그라운드 (service worker)
   선택 감지 / 🔍 아이콘                      단축키 수신
   카드 표시·위치 계산                        ③ 검색 출처(provider) 호출
                                              최근 결과 캐시
④ 설정 화면 (options page)  ── chrome.storage.local ──  ①
```

| 단위 | 책임 | 의존 |
|---|---|---|
| ① content script | 선택 감지, 아이콘, 카드 렌더링(Shadow DOM), 위치 계산, 외부 클릭·Esc 닫기 | ② (메시지), 설정 저장소 |
| ② background | `chrome.commands` 단축키 수신 → 활성 탭에 알림, 검색 요청 처리, 캐시 | ③ |
| ③ provider | 출처 API 호출 → 공통 결과 형식으로 변환, 관련성 판정 | `fetch` |
| ④ options | 아이콘 켜기·끄기 저장, 단축키 설정 화면(`chrome://extensions/shortcuts`) 열기 | 설정 저장소 |

순수 로직(입력 → 출력)은 별도 모듈로 분리해 단위 테스트한다:
선택 문자열 검증, 검색 URL 생성, 위키백과 응답 변환·관련성 판정, 카드 위치 계산.

### 4.1 공통 결과 형식

```ts
type LookupResult =
  | { status: 'found'; title: string; extract: string; url: string; isDisambiguation: boolean }
  | { status: 'not_found' }
  | { status: 'rate_limited' }
  | { status: 'network_error' };

interface LookupProvider {
  lookup(query: string): Promise<LookupResult>;
}
```

이번 범위의 구현은 `WikipediaKoProvider` 하나. 다른 출처(네이버, AI 요약 등)는 같은 인터페이스로 추가한다.

### 4.2 메시지

| 방향 | 메시지 | 내용 |
|---|---|---|
| ① → ② | `lookup` | `{ query }` → 응답 `LookupResult` |
| ② → ① | `trigger-from-shortcut` | 단축키가 눌렸으니 현재 선택으로 검색 시작 |

## 5. 동작 흐름

1. 사용자가 텍스트를 드래그한다 (`mouseup`).
2. ①이 선택 규칙(5.1)을 통과하면 선택 끝 근처에 🔍 아이콘을 띄운다 (설정에서 꺼져 있으면 생략).
3. 아이콘 클릭 → ①이 즉시 카드를 "찾는 중…" 상태로 띄우고 ②에 `lookup` 요청.
   단축키 → ②가 활성 탭의 ①에 `trigger-from-shortcut` 전달 → 이후 동일.
4. ②는 캐시에 있으면 바로 반환, 없으면 ③ 호출 후 캐시에 저장하고 반환.
5. ①이 결과로 카드를 채운다.

### 5.1 선택 규칙
- 앞뒤 공백 제거 후 1~50자일 때만 아이콘 표시
- `input`, `textarea`, `contenteditable` 안의 선택은 무시
- 확장 자신의 카드 안 선택은 무시
- 50자 초과 상태에서 단축키를 누르면 카드에 "선택이 너무 깁니다 (50자 이하)" 표시
- 다른 곳을 클릭하거나 선택이 해제되면 아이콘 제거

### 5.2 단축키
- 기본값 `Alt+Shift+F` / Mac `⌥⇧F` (`chrome.commands` `suggested_key`)
- 크롬 기본 단축키와의 충돌은 구현 시 Windows·Mac 실제 크롬에서 확인, 충돌 시 대체 조합으로 변경
- 사용자는 `chrome://extensions/shortcuts`에서 변경 가능

## 6. 위키백과 조회 (`WikipediaKoProvider`)

1. **정확 일치 조회**: `GET https://ko.wikipedia.org/api/rest_v1/page/summary/{query}`
   - 200 → `found` (리다이렉트 포함 — 예: `SaaS` → "서비스형 소프트웨어")
   - `type === 'disambiguation'` → `isDisambiguation: true`
   - 404 → 2단계로
2. **검색 후 관련성 판정**: `GET https://ko.wikipedia.org/w/api.php?action=query&list=search&srsearch={query}&srlimit=1&format=json`
   - 상위 1건의 제목이 질의를 포함할 때만(대소문자·공백 정규화) 그 제목으로 1단계 요약 조회 → `found`
     (예: `퍼널` → "마케팅 퍼널" 통과, `이탈률` → "유체이탈" 거부)
   - 아니면 `not_found`
3. HTTP 429 → `rate_limited` (재시도하지 않음)
4. 네트워크 오류·5xx·타임아웃(5초) → 1회 자동 재시도 후 `network_error`
5. 요청 헤더에 `Api-User-Agent: DragAndFind/<버전>` 포함 (위키미디어 API 이용 정책. 브라우저는 `User-Agent`를 바꿀 수 없어 이 헤더를 쓴다)

`extract`는 순수 텍스트로만 다루고 카드에는 `textContent`로 넣는다 (HTML 삽입 금지).

### 6.1 캐시
- 키: 정규화된 질의. 값: `found`·`not_found` 결과만 (오류는 저장하지 않음)
- 저장소: `chrome.storage.session` (브라우저 종료 시 삭제)
- 최대 200건, 넘으면 오래된 것부터 삭제

### 6.2 참고: 사전 확인 결과 (2026-10-23, 한국어 위키백과)
- 맞게 찾음 7/10: 온보딩, SaaS, 인플레이션, MZ세대, 레버리지, 퍼널(→마케팅 퍼널), PoC(→개념 증명)
- 엉뚱한 결과 3/10 → 관련성 판정으로 걸러야 함: 갓생(→세조), 리스킬링(→유재석), 이탈률(→유체이탈)
- 짧은 시간에 연속 요청(약 20회) 시 429 응답 (`retry-after: 26`)

## 7. 카드

### 7.1 구성
```
┌─────────────────────────────────┐
│ {제목}                       ✕  │
│ {요약 첫 문단, 최대 4줄}        │
│                  위키백과에서 보기 → │
├─────────────────────────────────┤
│  [ 구글 검색 ]   [ 네이버 검색 ]  │
└─────────────────────────────────┘
```
- 구글: `https://www.google.com/search?q={encodeURIComponent(query)}`
- 네이버: `https://search.naver.com/search.naver?query={encodeURIComponent(query)}`
- 버튼·링크는 새 탭으로 연다 (`target="_blank"`, `rel="noopener noreferrer"`)
- 구글·네이버 버튼은 모든 상태에서 항상 표시

### 7.2 상태별 본문
| 상태 | 본문 |
|---|---|
| 찾는 중 | "찾는 중…" |
| `found` | 제목 + 요약 + "위키백과에서 보기" |
| `found` (동음이의) | "뜻이 여러 개인 단어입니다" + "위키백과에서 보기" |
| `not_found` | "위키백과에 문서가 없습니다" |
| `rate_limited` | "요청이 많아 잠시 막혔습니다. 잠시 후 다시 시도해 주세요" |
| `network_error` | "연결에 실패했습니다" + [다시 시도] |
| 선택이 너무 김 | "선택이 너무 깁니다 (50자 이하)" (버튼 없음) |

### 7.3 위치
- 기준: 선택 영역의 `getBoundingClientRect()` 마지막 줄
- 기본: 선택 아래. 아래 공간이 카드 높이보다 작으면 선택 위로 뒤집는다
- 좌우: 화면 밖으로 나가지 않게 안쪽으로 밀어 넣는다
- 위아래 모두 부족하면 카드 최대 높이를 줄이고 카드 내부 스크롤
- 스크롤: 카드는 문서 좌표에 고정되어 선택한 단어를 따라 움직인다 (스크롤해도 닫지 않음)
- 닫기: ✕, 카드 바깥 클릭, Esc, 새 검색 시작

### 7.4 격리
- 카드와 아이콘은 Shadow DOM 안에 렌더링해 페이지 CSS와 서로 간섭하지 않게 한다

## 8. 설정 화면

- 🔍 아이콘 켜기·끄기 (기본: 켜짐) — `chrome.storage.local`
- 현재 단축키 표시(`chrome.commands.getAll`) + "단축키 바꾸기" 버튼 (`chrome://extensions/shortcuts` 열기)
- 처음 설치 시 별도 안내 화면 없음. 확장 설명란에 사용법 한 줄

## 9. 권한

| 권한 | 이유 |
|---|---|
| content script `matches: ['<all_urls>']` | 모든 페이지에서 선택 감지 (설치 시 "모든 웹사이트의 데이터 읽기·변경" 경고 — 이 기능상 불가피) |
| `host_permissions: ['https://ko.wikipedia.org/*']` | 위키백과 조회 |
| `storage` | 설정·캐시 |

크롬 정책상 `chrome://` 페이지, 크롬 웹스토어, 내장 PDF 뷰어에서는 동작하지 않는다.

## 10. 테스트

### 단위 (Vitest)
- 선택 문자열 검증: 빈 문자열, 공백만, 1자, 50자, 51자, 입력칸 안 선택
- 검색 URL 생성: 한글·공백·특수문자(`&`, `#`, `?`) 인코딩
- 위키백과 변환: 정확 일치, 리다이렉트, 동음이의, 404 → 검색 통과/거부(6.2의 사례를 고정 응답으로), 429, 5xx 재시도 1회
- 캐시: 적중, 오류 미저장, 200건 초과 시 삭제
- 카드 위치: 아래 배치, 위로 뒤집기, 좌우 밀어 넣기, 높이 축소

### E2E (Playwright, 확장 설치 크롬)
- 테스트용 로컬 페이지에서 드래그 → 🔍 표시 → 클릭 → 카드 표시 → 내용 확인
- 단축키로 검색
- 구글·네이버 버튼이 올바른 URL로 새 탭을 여는지
- Esc·바깥 클릭으로 닫힘
- 위키백과 요청은 가짜 응답으로 대체 (실제 호출 없음, 결과 고정, 위키백과 부하 방지)

## 11. 나중에 검토할 것
- 공개 전: 시각 디자인 시안, 웹스토어 등록 문구·아이콘·개인정보 처리 안내
- 출처 확장: 네이버 API(사용자 키 선택 입력), AI 요약, 영어 위키백과 대체 조회
