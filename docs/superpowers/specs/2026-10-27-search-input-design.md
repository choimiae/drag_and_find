# 카드에서 검색어 고쳐서 검색하기 — 설계 문서

- 작성일: 2026-10-27
- 상태: 사용자 검토 대기
- 기반 문서: `docs/superpowers/specs/2026-10-23-drag-and-find-design.md`, `docs/superpowers/specs/2026-10-24-visual-design-design.md`

## 1. 문제와 목적

새로 생긴 단어는 한국어 위키백과에 문서가 없는 경우가 많아, 결국 카드 아래 구글·네이버 버튼으로 검색하게 된다. 그런데 지금 버튼은 드래그한 글자를 그대로 검색어로 쓴다.

- 드래그한 글자에 조사가 붙는 경우("챗GPT를")
- 네이버에서 단어에 설명을 덧붙여 바로 검색하고 싶은 경우("챗GPT 뜻")

목적: 카드 안에서 검색어를 고친 뒤 구글·네이버로 검색할 수 있게 한다.

## 2. 범위

### 포함
- 카드 맨 아래 줄을 검색창 모양으로 바꾼다: 입력칸 + 작은 "구글"·"네이버" 글자 버튼 한 줄 (사용자가 시안 B의 한 줄 배치를 고르고, 버튼은 로고 모양 대신 글자로 정함)
- 입력칸에서 `Enter`를 누르면 설정에서 고른 검색 사이트로 검색
- 설정 화면에 "Enter로 검색할 곳"(네이버 / 구글) 추가, 기본값 네이버

### 제외
- 위키백과를 고친 검색어로 다시 찾기 (이번 요청은 구글·네이버 검색)
- 검색 기록, 자동 완성
- 다른 검색 사이트 추가
- 카드가 뜰 때 입력칸에 자동으로 커서 두기 (4.3 참고)

### 성공 기준
- "챗GPT를"을 드래그 → 입력칸에서 "를"을 지우고 "뜻"을 붙여 `Enter` → 네이버에서 "챗GPT 뜻" 검색 결과가 새 탭으로 열린다
- 입력칸에 글자를 치는 동안, 페이지가 보통 방식(버블 단계)으로 단 단축키가 동작하지 않는다 (한계는 4.3 참고)
- 개인정보 원칙은 그대로다: 누르거나 `Enter`를 칠 때만 그 사이트로 간다

## 3. 화면

```
┌────────────────────────────────┐
│ 챗GPT를                     ✕  │
│ 위키백과에 문서가 없습니다     │
├────────────────────────────────┤
│ [ 챗GPT를       ] [구글] [네이버] │
└────────────────────────────────┘
```

- 입력칸이 남은 너비를 모두 쓰고, 오른쪽에 "구글", "네이버" 글자 버튼이 붙는다. 순서는 지금처럼 구글, 네이버
- **회사 로고나 로고를 닮은 표시는 쓰지 않는다.** 시안 B의 "초록 네모 안 흰 N"은 네이버 앱 아이콘과 닮아 브랜드 사용 규정·웹스토어 심사에 걸릴 수 있다. 버튼은 회사 이름을 글자로만 적고, 색은 다른 버튼과 같은 카드 기본 색(`--dnf-text`, `--dnf-button`, `--dnf-border`)을 쓴다. 지금 쓰는 색 글자 "G"·"N" 표시(`.card-action-mark*`)도 없앤다
- 화면 낭독기 이름(`aria-label`)과 마우스를 올렸을 때 뜨는 글자(`title`)는 "구글 검색", "네이버 검색"
- 입력칸에도 화면 낭독기 이름("검색어")을 붙인다
- 입력칸 색·테두리는 카드 색 세트(`--dnf-*`)를 쓰고, 밝은·어두운 테마 모두 맞춘다. 포커스 표시는 지금 버튼과 같은 `--dnf-accent` 테두리
- 이 줄이 보이는 경우는 지금 버튼 줄과 같다: 찾는 중, 결과 있음, 문서 없음, 오류 모두. "선택이 너무 깁니다" 카드에는 지금처럼 없다

## 4. 동작

### 4.1 검색어
- 입력칸 처음 값은 지금 버튼이 쓰던 검색어와 같다(그 카드의 `query`). 다른 뜻을 눌러 카드가 그 제목으로 바뀌면 입력칸도 새 제목으로 바뀐다
- 같은 단어의 "찾는 중 → 결과" 사이, 그리고 "다시 시도"로 카드가 다시 그려져도 사용자가 고친 값을 유지한다. 입력칸에 커서가 있었다면 커서와 그 위치도 유지한다 — 커서가 사라지면 이어서 치는 키가 페이지로 가기 때문이다 (설계자 판단)
- 검색할 때 앞뒤 공백은 지운다. 지운 결과가 비어 있으면 아무 일도 하지 않는다
- 입력 길이는 따로 제한하지 않는다 (검색 주소는 지금처럼 `encodeURIComponent`로 만든다)

### 4.2 검색하기
- "구글" 또는 "네이버" 버튼: 입력칸 값으로 그 사이트 검색 결과를 새 탭으로 연다
- 입력칸에서 `Enter`: 설정의 "Enter로 검색할 곳"으로 연다
- 한글 입력 중(조합 중) 누른 `Enter`는 검색하지 않는다 — 글자 확정용 `Enter`이기 때문이다 (`isComposing` 또는 `keyCode 229`로 확인)
- 새 탭은 지금 버튼과 같은 방식으로 연다: `noopener noreferrer`. 버튼이 링크(`<a>`)든 버튼(`<button>`)이든 결과가 같으면 구현 방식은 빌더 판단. 단, 입력칸 값이 바뀌면 열릴 주소도 바로 반영돼야 한다(가운데 클릭·`Cmd+클릭`으로 열어도 고친 값으로)

### 4.3 키보드와 포커스
- 카드가 뜰 때 입력칸에 커서를 자동으로 두지 않는다. 페이지를 읽다가 누른 키가 입력칸으로 들어가는 것을 막기 위해서다
- 입력칸에서 `Esc`: 지금처럼 카드를 닫는다
- 입력칸에서 일어난 키 이벤트(`keydown`·`keyup`·`keypress`)는 입력칸에서 `stopPropagation`으로 페이지로 퍼지지 않게 막는다. Shadow DOM 밖에서는 이벤트 대상이 카드 전체로 보여서, 페이지가 "입력 중"인 줄 모르고 자기 단축키를 실행하기 때문이다. 단 `Esc`로 카드 닫기는 계속 동작해야 한다 (지금 `document` 캡처 단계 리스너가 처리하므로 영향 없음)
- **알려진 한계 (설계자 판단)**: 페이지가 `window`·`document`에 캡처 단계로 단 키 리스너는 입력칸보다 먼저 불리므로 막지 못한다. 이것까지 막으려면 콘텐츠 스크립트를 페이지보다 먼저(`document_start`) 실행하도록 구조를 바꿔야 하는데, 위험과 범위에 비해 얻는 것이 작아 이번에는 하지 않는다. 실제로 문제가 되는 사이트가 나오면 따로 다룬다
- 입력칸 안에서 글자를 드래그해 선택해도 돋보기 아이콘이 새로 뜨거나 카드가 닫히지 않아야 한다 (지금도 카드 안 클릭은 무시하므로 같은 규칙이 입력칸에도 적용되는지 확인)

### 4.4 설정
- `Settings`에 `searchEngine: 'naver' | 'google'` 추가, 기본값 `'naver'`
- 저장된 값이 없거나 형식이 틀리면 기본값 (기존 `parseSettings` 방식과 같다). 이미 설치한 사용자도 업데이트 후 네이버로 시작한다
- 설정 화면: 카드 테마와 같은 모양의 두 칸 선택(`segmented`)으로 "Enter로 검색할 곳: 네이버 | 구글". 위치는 카드 테마 아래. 짧은 안내 문구: "카드의 검색어 칸에서 Enter를 누르면 이 사이트로 검색합니다."
- 설정을 바꾸면 이미 열린 탭의 카드에도 바로 반영된다(테마와 같은 방식). 최소한 다음 `Enter`부터는 새 설정을 따라야 한다
- 설정을 읽지 못하면(확장 업데이트 직후 끊긴 탭 등) 기본값 네이버로 검색한다

## 5. 바뀌는 곳 (예상)

| 파일 | 변경 |
|---|---|
| `lib/settings.ts` | `searchEngine` 타입·기본값·검증 |
| `lib/options-page.ts`, `entrypoints/options/index.html` | 새 설정 항목 |
| `lib/ui/card.ts`, `lib/ui/styles.ts` | 검색 줄 모양과 동작 |
| `lib/ui/overlay.ts`, `lib/content/controller.ts`, `entrypoints/content.ts` | 설정값 전달, 키 이벤트 처리 |
| `lib/search-urls.ts` | 필요하면 사이트 이름으로 주소를 고르는 함수 |
| `PRIVACY.md`, `docs/store/listing.md`, `README.md` | "검색어를 고쳐서 검색할 수 있다"는 설명 보강 (보내는 곳은 그대로) |

권한(`permissions`, `host_permissions`)은 바뀌지 않는다. 따라서 업데이트 시 사용자에게 새 권한 승인 창이 뜨지 않는다.

## 6. 시험

- 단위: 설정 검증(값 없음·잘못된 값·정상 값), 카드 검색 줄(처음 값, 고친 값으로 주소 생성, 빈 값 무시, `Enter` 사이트 선택, 조합 중 `Enter` 무시, 다시 그려도 고친 값·커서 유지, 다른 뜻 선택 시 새 제목), 설정 화면 새 항목 저장
- E2E: 드래그 → 입력칸 수정 → `Enter` → 새 탭 주소가 고친 검색어의 네이버 검색 주소인지 확인. 입력칸에 글자를 칠 때 시험 페이지가 `document`에 버블 단계로 단 `keydown` 리스너가 불리지 않는지 확인
- 스토어 스크린샷은 카드 모양이 바뀌므로 `pnpm store:images`로 다시 만든다

## 7. 빌더에게 맡기는 것

- 검색 줄 마크업 구조(`form` 사용 여부 등)와 CSS 세부 값
- 카드 상태를 다시 그릴 때 고친 값을 어디에 보관할지
- 설정값을 카드까지 전달하는 경로
