# 관리자 통합 대시보드 설계

- 작성일: 2026-11-10
- 승인: 대화에서 소유자 전용 Cloudflare 관리자 웹 앱과 단계별 구축에 동의

## 목적과 범위

maestro가 한 주소에서 Chrome Web Store 성과, 확장의 실제 조회 사용량, Cloudflare 조회 Worker 상태를 확인한다. 관리자 앱은 확장 패키지나 공개 조회 Worker와 별도로 배포한다. 상시 실행하는 자체 서버는 두지 않는다. 첫 배포는 기존 스토어·Worker 통계를 연결하고, 다음 확장 업데이트에서 조회 사용량 수집을 추가한다.

첫 화면은 오늘·최근 7일·최근 30일 기간 선택, 핵심 수치, 일별 추이, 각 데이터의 마지막 갱신 시각을 제공한다. 상세 지역·운영체제 분석, 알림, 사용자별 이력, 검색어 분석은 이번 범위에 포함하지 않는다.

## 화면 구성과 시각 디자인

화면은 탭을 오가지 않는 한 페이지로 만든다. 데스크톱 상단에는 Drag and Find 아이콘·제목, 마지막 갱신 시각, 기간 선택, 새로고침을 둔다. 다음 줄에는 조회 기능 사용 설치 수·단어 조회 건수·웹스토어 설치·Worker 오류를 네 칸으로 배치한다. 그 아래에는 일별 조회 추이와 Worker 현재 상태를 나란히 보여 준다. 마지막에는 확장 사용·Chrome Web Store·Cloudflare Worker의 상세 수치를 세 칸으로 배치한다. 화면 폭이 좁으면 같은 순서를 유지하며 두 칸 또는 한 칸으로 접는다. 기간 선택은 모든 영역에 적용한다.

확장 카드의 시각 규칙을 그대로 따른다. 시스템 글꼴, 흰 바탕(`#ffffff`), 대체 바탕(`#fafbfc`), 본문 글자(`#1d2129`), 보조 글자(`#5f6b7a`), 테두리(`#e3e6ea`), 12px 모서리와 부드러운 그림자를 사용한다. 제목 영역에는 초록(`#03c75a`)에서 파랑(`#1a73e8`)으로 이어지는 4px 색띠를 두고, 강조 수치에는 연한 파랑 바탕(`#f3f8ff`)과 테두리(`#d6e6fd`)를 쓴다. 새로고침 버튼은 카드의 파랑(`#1a73e8`)을 사용한다. 그래프는 날짜 축, 조회 건수 눈금, 가로 기준선을 갖추고 날짜별 조회 완료 건수를 막대 위에 표시한다. 막대는 강조색보다 차분한 연한 파랑(`#a9c9f3`) 단색으로 표시하고 그라데이션을 넣지 않는다. 상태는 색뿐 아니라 '정상', '오류', '연결 필요' 텍스트로도 구분한다. 어두운 크롬 설정에는 기존 카드의 어두운 색 세트를 적용한다.

시안은 `.superpowers/brainstorm/49852-1794275185/content/layout-card-style-v3.html`에 있다. 시안 숫자는 모두 예시이며, 실제 화면은 연결 전 빈 상태와 연결 오류를 구분해 표시한다.

## 구성과 접근 제어

`관리자 브라우저 → Cloudflare Access → 관리자 Worker(정적 화면 + /api/*) → 외부 통계 API`로 구성한다. 관리자 Worker는 정적 화면과 API 경로를 한 번에 배포한다. 기존 `drag-and-find-lookup` Worker에는 관리자 API를 넣지 않는다. Cloudflare Access의 허용 정책에는 maestro가 지정한 Google 계정 하나만 등록한다. 관리자 Worker의 배포 주소와 미리보기 주소까지 접근 정책이 적용되는지 배포 검증에서 확인한다. 정적 자산과 API 요청을 모두 Worker가 먼저 받아 Access JWT의 서명·대상·소유자 이메일을 검증한다. 설정이나 JWT가 없으면 모든 경로를 거부한다.

Chrome Web Store와 GA4 보고서에 읽기 권한을 부여한 Google 서비스 계정 키, Cloudflare Account Analytics 읽기 토큰은 관리자 Worker의 Secret에 저장한다. 브라우저에는 통계 결과만 전달하며 토큰·원본 인증 응답은 반환하지 않는다. 외부 API 호출은 서버에서만 수행하고, 관리자 API 응답은 `Cache-Control: no-store`로 제공한다. 비밀값은 저장소·빌드 산출물·로그에 남기지 않는다.

## 데이터와 표시 기준

| 영역 | 출처 | 표시 항목 | 해석 |
| --- | --- | --- | --- |
| 스토어 | Chrome Web Store API V2 `queryMetrics` | 설치, 삭제, 페이지 조회, 노출, 스토어 이용자 | 스토어의 집계값이며 실제 단어 조회 인원과 다름 |
| 확장 사용 | GA4 Data API | 조회 기능을 사용한 설치 수, 조회 성공·실패 건수 | 설치별 식별자 기준의 근사치이며 고유한 사람 수가 아님 |
| Worker | Cloudflare GraphQL Analytics API | 요청 수, 오류 수, 일별 추이 | Worker 전체 호출이므로 조회 건수와 같지 않음 |
| 현재 상태 | 조회 Worker `/lookup` 실요청 | HTTP 결과, 결과 형식, 응답 시간, 확인 시각 | 외부 네이버·위키백과 장애도 결과에 반영됨 |

각 영역은 동일한 날짜 범위를 사용하되 출처별 시간대와 갱신 지연을 표시한다. 서로 다른 출처의 숫자를 합쳐 하나의 '사용자 수'로 제시하지 않는다. 한 출처가 실패하면 해당 영역에 오류와 마지막 성공 시각을 표시하고 다른 영역은 계속 보여준다. 실요청 상태 확인은 사용자가 새로고침하거나 화면을 열 때 수행하고, 호출 빈도를 제한해 네이버 API를 불필요하게 소모하지 않는다.

## 단계 1: 관리자 앱과 기존 통계

새 `admin/` 앱에 화면, 인증된 API 경로, Chrome Web Store·Cloudflare 어댑터를 둔다. 스토어 연결에는 게시자 계정에 등록한 Google 서비스 계정으로 `chromewebstore.readonly` 범위의 단기 토큰을 발급받는다. Cloudflare 연결에는 대상 계정으로 범위를 제한한 `Account Analytics: Read` 토큰을 사용한다. 인증이 준비되지 않은 영역은 예시 숫자를 실제 값처럼 표시하지 않고 '연결 필요'로 표시한다.

배포 전에는 샘플 응답으로 화면과 오류 상태를 확인한다. 배포 후에는 Access 차단, 허용 계정 로그인, 실제 두 API의 수치, 조회 Worker 실요청을 확인한다. 이 단계에서는 확장 코드와 개인정보 처리방침을 바꾸지 않는다.

## 단계 2: 확장 조회 사용량

확장 백그라운드에서 조회가 끝난 뒤 `lookup_completed` 또는 `lookup_failed` 이벤트를 전송한다. 결과를 찾지 못한 정상 응답도 `lookup_completed`로 세고, 모든 조회 경로가 오류로 끝난 경우만 `lookup_failed`로 센다. Worker 장애 후 직접 위키백과에서 결과를 얻은 경우도 완료 이벤트 한 번으로 센다. 설치별 무작위 식별자를 `chrome.storage.local`에 보관한다. 이벤트에는 식별자, 이벤트 종류, 확장 버전만 포함하고 검색어·방문 URL·페이지 내용·주변 문맥·조회 결과 텍스트는 포함하지 않는다. 이벤트 전송은 조회 결과 표시를 기다리게 하거나 실패시키지 않는다.

이벤트는 공개 조회 Worker의 별도 `/telemetry` 경로로 보내고, 이 Worker가 Secret에 보관한 GA4 Measurement Protocol 인증 정보로 전달한다. 경로는 허용된 이벤트와 필드만 받고 본문 크기·요청 빈도를 제한한다. 관리자 앱은 GA4 Data API에서 이 이벤트의 기간별 건수와 설치별 사용 수를 읽는다. 식별자를 쓰므로 이 수집을 '무식별'로 설명하지 않는다.

확장 업데이트 전에 `README.md`, `PRIVACY.md`, `docs/store/listing.md`의 통계 수집·전송처·식별자 설명과 웹스토어 개인정보 고지를 수정한다. 새 확장 버전이 배포된 이후의 데이터만 집계한다. GA4 보고서 지연과 측정 오차를 화면에 안내한다.

## 검증과 완료 기준

- 관리자 외 계정은 화면과 `/api/*`에 접근할 수 없고, 허용 계정은 배포 주소에서 로그인해 볼 수 있다.
- 스토어 API의 선택 기간 수치와 Cloudflare 통계가 각 원본 화면의 동일 기간 수치와 합리적으로 일치한다. 차이가 있으면 시간대·집계 지연을 확인한다.
- 한 API의 인증 만료·실패·빈 데이터가 다른 영역 표시를 막지 않는다. 비밀값은 클라이언트 응답과 로그에 없다.
- Worker 현재 상태는 실제 `/lookup` 요청의 HTTP 상태·응답 형식·시간을 보여 준다.
- 확장 조회 성공·실패·Worker 장애 후 직접 위키백과 전환에서 이벤트가 한 번만 기록되고, 이벤트 실패가 카드 동작에 영향을 주지 않는다.
- GA4에는 검색어·URL·본문이 전송되지 않는다. 조회 사용 설치 수는 사람 수가 아니라는 설명이 화면에 있다.
- 저장소의 형식·린트·타입·단위·E2E 검사를 통과한다. 실제 API와 배포 확인은 테스트 대역 결과와 구분해 검증한다.
