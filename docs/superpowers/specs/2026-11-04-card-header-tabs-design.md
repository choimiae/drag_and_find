# 카드 헤더 탭과 직접 찾기 설계

## 목적과 선택한 방향

카드의 주된 용도는 뜻 설명을 읽는 것이다. 검색어 입력칸과 구글·네이버 버튼을 항상 하단에 두면 설명 공간이 줄어든다. 제목과 닫기 버튼 아래에 `뜻 보기 | 직접 찾기` 탭을 두고, 기본값인 `뜻 보기`에서는 설명에 카드 공간을 사용한다.

하단에 검색 위치 선택을 계속 두는 방식은 설명 공간을 차지한다. 헤더에서 별도 팝오버를 여는 방식은 읽던 내용 위를 가린다. 두 화면을 탭으로 나누면 직접 찾기를 찾기 쉬우면서 읽는 동안 검색 UI가 보이지 않는다. `자동 검색`이라는 이름은 현재 결과를 보는 화면의 의미를 충분히 설명하지 못하므로 `뜻 보기`를 쓴다.

## 화면과 동작

- 카드 폭과 제목·닫기 버튼·뜻 목록·출처 표기는 현재 구조를 유지한다. 헤더에는 제목 줄 다음에 두 탭을 둔다.
- `뜻 보기`에는 로딩·결과·오류 메시지와 출처를 표시한다. 내용이 길면 본문 한 곳에서만 스크롤하고 제목·탭·출처는 고정한다.
- `직접 찾기`에는 현재 검색어가 채워진 입력칸과 같은 줄의 작은 `뜻 찾기` 버튼을 표시한다. 그 아래 `웹에서 검색` 구역에 로고나 임의 이니셜 없이 `구글에서 찾기 ↗`, `네이버에서 찾기 ↗` 링크를 나란히 둔다. 검색 대상 선택 탭을 중첩하지 않는다.
- 탭을 오가도 뜻 목록의 스크롤 위치와 입력 중인 값·커서 위치를 유지한다. 직접 찾기 탭을 열 때 입력칸에 자동으로 포커스를 옮기지 않는다.
- 입력칸에서 Enter 또는 `뜻 찾기` 버튼을 누르면 같은 단어를 카드 안에서 조회한다. 한글 조합 중 Enter는 글자 확정에만 사용한다.
- 직접 조회를 시작하면 `뜻 보기` 탭으로 전환하고 로딩을 표시한다. 성공·실패 결과는 기존 카드 조회 흐름으로 보여 준다. 연속 조회에서는 마지막 요청의 결과만 표시한다.
- 직접 조회는 선택한 웹페이지의 주변 문맥을 사용하지 않는다. 뜻 상세 화면에서 새 단어를 찾으면 이전 뜻 목록으로 돌아가는 상태는 종료한다.
- 입력 값의 앞뒤 공백을 제거해 카드 조회에 사용한다. 1~50자 범위를 벗어나면 요청하지 않고 직접 찾기 화면에 짧은 입력 오류를 표시한다. 구글·네이버 링크의 입력 길이는 기존처럼 별도로 제한하지 않는다.
- 구글·네이버 링크는 입력한 값을 검색어로 사용하며, 사용자가 누를 때만 각각 새 탭을 연다. Enter는 외부 검색을 열지 않는다. 빈 입력에서는 카드 조회와 외부 링크를 실행하지 않는다.
- 처음부터 선택한 글이 너무 긴 상태의 안내 카드는 현재처럼 탭 없이 표시한다.

## 설정과 데이터 흐름

- 옵션 화면의 `Enter로 검색할 곳` 설정을 제거한다. 저장 설정에서는 `showIcon`과 `theme`만 읽고 쓴다. 이미 저장된 `searchEngine` 필드는 무시한다.
- 직접 조회는 기존 `content script → background → Worker → 백과 출처` 흐름을 사용한다. 선택한 단어로 처음 조회할 때와 같은 장애 시 위키백과 대체 조회를 사용한다.
- `README.md`, `PRIVACY.md`, `docs/store/listing.md`에서 Enter와 설정·외부 사이트 전송 설명을 새 동작에 맞게 바꾼다.

## 구현 경계와 검증

- 카드 렌더러는 탭·입력·외부 링크를 제어하고, 콘텐츠 컨트롤러는 직접 입력한 검색어로 기존 조회 함수를 호출한다. 옵션 화면과 설정 파서는 검색 사이트 선택을 제거한다.
- 단위 테스트는 탭 전환, 스크롤·입력 보존, 버튼·Enter의 같은 조회, 한글 조합, 빈 값·길이 오류, 외부 링크 URL, 설정 이전 값을 확인한다.
- E2E는 Chromium 확장에서 선택 → 카드 → 직접 찾기 → Enter → 새 카드 결과와 구글·네이버 새 탭을 확인한다. 외부 서비스 응답은 가짜 값으로 대체한다.
- 스토어에 보이는 화면이 바뀌므로 스크린샷을 다시 만들고 README 이미지와 스토어 등록 이미지를 확인한다.
