# 뜻이 여러 개인 단어 표시 개선 — 설계 문서

- 작성일: 2026-10-24
- 상태: 사용자 검토 대기
- 경로: Superpowers brainstorming → architectural (단계 사이에 주고받는 데이터 모양이 바뀜)
- 기반 문서: `docs/superpowers/specs/2026-10-23-drag-and-find-design.md`

## 1. 문제와 목적

일반 단어(모델, 플랫폼, 버블, 트리거 등)는 한국어 위키백과에서 대부분 **뜻 모음 문서**(동음이의 문서)라서, 지금 카드는 "뜻이 여러 개인 단어입니다"와 위키백과 링크만 보여 준다. 실제로 써 보니 이 문구가 너무 자주 뜬다.

목적: 뜻 모음 단어일 때도 카드 안에서 뜻을 바로 알 수 있게 한다.
- 문맥상 뜻을 확신할 수 있으면 그 뜻을 맨 위에 보여 준다
- 기본 뜻이 있으면 보여 준다
- 다른 뜻 목록을 보여 주고, 누르면 그 뜻의 요약으로 바꾼다

## 2. 사전 시험 결과 (2026-10-24, 버릴 코드로 측정)

직접 쓴 기사풍 문장 13개(뜻 모음 단어 9개)로 측정했다.

| 방식 | 맞힘 | 틀림 | 고르지 않음 |
|---|---|---|---|
| 뜻 목록의 짧은 줄과 문맥 비교 | 2 | 3 | 6 (11개 중) |
| 연결 문서 첫 문단과 비교, 1등 선택 | 6 | 7 | 0 |
| **연결 문서 첫 문단과 비교, 엄격 기준(겹침 ≥3, 2등 대비 ≥1.5배)** | **6** | **1** | **6** |

- 엄격 기준은 같은 13문장으로 정했으므로 실제 정확도는 이보다 낮을 수 있다
- 13문장 중 2개("모델", "트리거")는 뜻 목록을 먼저 본 뒤 쓴 문장이다
- 엔진·바이러스·캐시·쿠키는 뜻 모음 문서가 아니라 대표 뜻 문서여서 시험에서 뺐다(이 기능 범위 밖)

## 3. 범위

### 포함
- 뜻 모음 결과에 기본 뜻, 다른 뜻 목록, 문맥 기반 자동 선택 추가
- 다른 뜻 항목을 누르면 그 제목으로 다시 찾기
- 페이지 쪽에서 선택 주변 문맥 수집, 찾기 요청에 포함
- 사전 시험 13문장을 고정 회귀 테스트로 추가

### 제외
- 뜻 목록으로 돌아가기 버튼 (단어를 다시 드래그하면 됨. 필요하면 나중에)
- 대표 뜻 문서(엔진, 캐시 등)에서 다른 뜻 찾기
- AI 기반 뜻 고르기
- 21개 이상 연결된 뜻 모음 문서의 나머지 후보 추가 조회 (6.3 참고)
- 문장형 항목 줄("마진(摩震)은 … 이다.")은 어떤 연결 문서 제목으로도 시작하지 않아 누를 수 없다 — 후속 과제: 항목별 링크 추출(HTML extract 또는 action=parse) — 2026-10-28 `meaning-links` 설계로 해결

## 4. 화면

```
┌────────────────────────────────┐
│ 트리거                      ✕  │
│ 이 글에서는 아마               │  ← suggestion 있을 때만
│ ▸ 데이터베이스 트리거           │     (누르면 그 뜻의 요약으로 카드 전환)
│   테이블에 변경이 생기면 자동… │     첫 문단 최대 3줄
│ ─ 기본 뜻 ─                    │  ← basic 있을 때만
│ 총의 방아쇠를 뜻하는 사격용어. │
│ ─ 다른 뜻 ─                    │
│ · 방아쇠                       │  ← title 있는 항목: 누를 수 있음
│ · 트리거 전략                  │  ← title 없는 항목: 글자만
│ … 외 4개                       │
│              위키백과에서 보기 →│
│ [구글 검색]  [네이버 검색]     │
└────────────────────────────────┘
```

- "다른 뜻"은 최대 8개, 넘으면 "외 N개"
- 항목 글자는 최대 40자, 넘으면 "…"
- suggestion으로 고른 뜻은 "다른 뜻" 목록에서 뺀다
- 항목을 누르면 카드가 "찾는 중…"이 된 뒤 그 제목의 결과로 바뀐다 (기존 찾기와 같은 흐름, 문맥 없이)
- `disambiguation`이 없는 뜻 모음 결과(추가 요청 실패 등)는 지금처럼 "뜻이 여러 개인 단어입니다" + 위키백과 링크
- 문구(정확히 이대로): `이 글에서는 아마`, `기본 뜻`, `다른 뜻`, `외 N개`
- 모든 외부 글자는 `textContent`로만 넣는다

## 5. 데이터 모양

### 5.1 결과 (`lib/lookup/types.ts`)

```ts
/** 뜻 모음 문서의 한 항목. title이 있으면 눌러서 그 문서를 찾을 수 있다. */
interface Meaning {
  label: string;
  title: string | null;
}

/** 자동 선택 후보이자 "이 글에서는 아마"에 보여 줄 뜻. */
interface SenseCandidate {
  title: string;
  extract: string;
  url: string;
}

interface DisambiguationInfo {
  basic: string[];             // 기본 뜻 문장들 (없으면 빈 배열)
  meanings: Meaning[];         // 목록 순서 그대로
  candidates: SenseCandidate[]; // 첫 문단이 있는 연결 문서 (6.2)
}

type LookupResult =
  | {
      status: 'found';
      title: string;
      extract: string;
      url: string;
      isDisambiguation: boolean;
      disambiguation?: DisambiguationInfo; // 뜻 모음이고 추가 요청이 성공했을 때만
      suggestion?: SenseCandidate;         // 문맥으로 확신했을 때만
    }
  | { status: 'not_found' } | { status: 'rate_limited' } | { status: 'network_error' };
```

- `isLookupResult`는 새 필드가 있으면 모양까지 검사한다(문자열·배열·null 여부)
- 캐시는 `suggestion`을 빼고 저장한다(문맥마다 다르므로)

### 5.2 찾기 요청 (`lib/messages.ts`)

```ts
interface LookupRequest {
  type: 'lookup';
  query: string;
  context?: string; // 선택 주변 문맥, 최대 250자 (앞 100 + 선택 최대 50 + 뒤 100)
}
```

- `isLookupRequest`: `context`가 있으면 문자열이어야 한다
- 백그라운드는 250자를 넘는 `context`를 250자로 자른다

## 6. 동작

### 6.1 문맥 수집 (페이지 쪽)
- 선택의 `anchorNode`에서 가장 가까운 블록 요소(`p, li, td, dd, blockquote, h1~h6, article, section, div`)의 `textContent`를 쓴다
- 그 안에서 선택 글자를 찾아 앞 100자 + 선택 + 뒤 100자를 문맥으로 한다
- 찾지 못하면 블록 글자 앞쪽 200자를 쓴다
- 블록 글자의 줄바꿈·연속 공백은 공백 하나로 합친다
- 순수 함수 `extractContext(blockText, selectedText): string`로 분리해 테스트한다

### 6.2 뜻 모음 정보 얻기 (백그라운드, `WikipediaKoProvider`)
요약 결과가 `type === 'disambiguation'`이면 2번 더 요청한다:

1. 본문 글자: `w/api.php?action=query&prop=extracts&explaintext=1&titles={제목}&format=json`
2. 연결 문서 첫 문단(한 번에): `w/api.php?action=query&generator=links&titles={제목}&gplnamespace=0&gpllimit=50&prop=extracts&exintro=1&explaintext=1&exlimit=20&exchars=300&format=json`

본문 글자 해석 (순수 함수 `parseDisambiguationText`):
- 첫 줄(소개 문장)은 버린다
- `== 제목 ==` 형식의 줄은 묶음 이름. "같이 보기" 묶음과 그 이후는 버린다
- 이름에 "기본"이 들어간 첫 묶음의 줄들 → `basic`
- 나머지 줄들 → 항목. `label` = `:` 앞부분이 있으면 그것, 없으면 줄 전체

항목과 연결 문서 짝짓기:
- 첫 문단이 있는 연결 문서 제목 중, 항목 줄이 그 제목으로 **시작하는** 가장 긴 것을 `title`로 한다 (예: "데이터 모델: 데이터의 관계…" → "데이터 모델")
  - 여기서 연결 문서 제목에는 첫 문단이 없는 넘겨주기 문서도 포함한다(없는 문서는 제외). 넘겨주기 문서는 첫 문단이 비어 있어도 눌러서 열 수 있다. `candidates`는 그대로 첫 문단이 있는 것만
- 짝이 없으면 `title: null`
- `candidates` = 첫 문단이 있는 **모든** 연결 문서. 단, 뜻 모음 문서 자신과 "위키낱말사전"은 뺀다
  - 처음에는 "항목 줄이 그 제목으로 시작하는 것"만 후보로 삼으려 했으나, 같은 시험 문장으로 다시 재 보니 맞힘 4·틀림 2로 나빠졌다
    ("경제 버블" 줄의 연결 문서는 "거품 경제", "버스 터미널"은 줄 중간에 있음). 모든 연결 문서를 후보로 하면 맞힘 6·틀림 1이다
  - 설명 문장 안에 걸린 엉뚱한 연결 문서("생산", "궁예" 등)도 후보에 들어가지만, 문맥과 겹치는 글자가 적어 거의 뽑히지 않는다
- `meanings`의 `title` 짝짓기(누를 수 있는 항목)는 위 "가장 긴 시작 제목" 규칙을 그대로 쓴다

실패 처리:
- 두 요청 중 하나라도 실패(429·연결 오류·형식 오류)하면 `disambiguation` 없이 기존 결과를 돌려준다
- 이 경우 캐시에 저장하지 않는다(다음에 다시 시도할 수 있게)

### 6.3 자동 선택 (순수 함수 `pickSense(context, word, candidates)`)
- 문맥과 각 후보(제목 + 첫 문단)에서 찾은 단어를 지우고, 문장부호·공백을 뺀 뒤 두 글자 조각 집합을 만든다
- 점수 = 겹친 조각 수 ÷ √(후보 조각 수)
- 1등의 겹친 조각 수 ≥ 3 **이고** 1등 점수 ≥ 2등 점수 × 1.5 일 때만 1등을 고른다
- 문맥이 없거나 후보가 없으면 고르지 않는다
- 선택은 백그라운드의 조회 서비스가 캐시를 읽은 뒤 매번 계산한다
- 한계: 연결 문서 첫 문단은 한 번에 20개까지만 받는다. 연결이 20개를 넘는 문서는 일부 후보에 첫 문단이 없을 수 있다

### 6.4 다른 뜻 누르기
- 카드 → 컨트롤러로 "이 제목 찾기"를 알리면, 컨트롤러는 같은 위치(anchor)에 문맥 없이 그 제목으로 찾기를 시작한다
- 이후 흐름(찾는 중, 늦게 온 응답 무시, 닫기)은 기존 찾기와 같다

## 7. 요청 수와 성능
- 뜻 모음 단어: 요청 3번(요약 1 + 추가 2). 결과는 캐시
- 뜻 모음이 아닌 단어: 지금과 같음
- 위키백과 429 대비는 기존 규칙(재시도 안 함, 해당 상태 표시) 그대로

## 8. 테스트

### 단위
- `parseDisambiguationText`: 사전 시험에서 받은 실제 문서 글자(모델, 트리거, 버블, 플랫폼, 커널, 마진, 포트, 터미널, 스레드)로 basic·항목·같이 보기 제외 확인
- 항목·연결 문서 짝짓기: 가장 긴 제목 우선, 설명 속 연결 문서 제외
- `pickSense`: **사전 시험 13문장 고정 테스트**. 문장별 기대 결과를 고정한다(맞힘 6 · 틀림 1 · 고르지 않음 6, 틀린 1개는 패션 "모델" → "모델 (드라마)")
- `extractContext`: 앞뒤 100자, 블록 안에 없을 때, 짧은 블록
- 제공자: 뜻 모음일 때 요청 3번, 추가 요청 실패 시 기존 결과, 일반 문서는 요청 1번
- 조회 서비스: 캐시에 `suggestion` 미저장, 문맥마다 선택 재계산, `disambiguation` 없는 뜻 모음은 미저장
- 메시지 검증: `context` 문자열 검사, 새 결과 필드 모양 검사
- 카드: suggestion·기본 뜻·다른 뜻 표시, 8개 초과 "외 N개", 40자 자르기, 누를 수 없는 항목, 항목 누르기 처리기 호출, 외부 글자 HTML 미해석
- 컨트롤러: 문맥이 요청에 담기는지, 다른 뜻 누르면 같은 위치에서 제목으로 찾기

### E2E
- 가짜 위키백과 응답으로 뜻 모음 단어 찾기 → suggestion과 다른 뜻 표시 → 다른 뜻 누르면 그 요약으로 바뀜
