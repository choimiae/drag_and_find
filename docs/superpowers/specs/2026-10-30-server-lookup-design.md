# 서버 중심 단어 조회 설계

- 작성일: 2026-10-30
- 승인: 대화에서 서버가 출처 순서를 관리하는 구조로 확정

## 목적과 범위

확장이 선택한 단어를 Cloudflare Worker로 보내면 Worker가 NAVER API HUB 백과 검색을 먼저 호출한다. 결과가 0건이거나 한도 초과이면 한국어 위키백과를 조회한다. Worker가 공통 결과 하나와 출처를 돌려주고 확장은 카드로 표시한다. 네이버 인증 정보는 Worker Secret에만 둔다. 우리말샘은 이번 범위에 넣지 않는다.

## 흐름과 경계

`content script → background → Worker → 네이버 백과 / 위키백과 → background → content script`.

- Worker 입력은 정리된 검색어 1~50자다. 주변 문맥은 Worker로 보내지 않는다.
- 네이버 요청은 `GET /search/v1/encyc?query=...&display=1&start=1&format=json`이고 API HUB 인증 헤더를 사용한다. 첫 결과의 제목, 설명, 원문 링크를 반환한다. 검색 결과의 순서와 뜻을 재작성하지 않는다.
- 네이버 응답이 0건이거나 429이면 위키백과를 조회한다. 네이버 5xx·연결 오류도 사용자 조회를 위해 위키백과로 넘긴다. 인증·설정 오류는 서버 로그에 원인을 남기고 사용자에게는 위키백과를 보여 준다.
- 네이버 429는 일일/초당 한도 모두 가능하므로 해당 요청만 위키백과로 넘긴다. 하루 전체 소진 상태로 단정해 저장하지 않는다.
- 위키백과 조회와 동음이의 해석은 기존 `WikipediaKoProvider`를 Worker에서 재사용한다. 주변 문맥 기반 추천은 확장에서 계산한다.
- Worker 응답의 `found`에는 `source: 'naver' | 'wikipedia'`를 포함한다. 카드에는 실제 출처 이름과 원문 링크를 표시한다. 네이버 설명의 검색 강조 태그는 안전하게 렌더링한다.
- 두 출처 모두 결과가 없으면 `not_found`, 둘 다 실패하면 기존 오류 상태를 반환한다.

## 캐시와 보안

- 네이버 우선순위를 매 요청마다 지키기 위해 새 조회 흐름에서는 확장과 Worker 모두 결과를 캐시하지 않는다.
- Worker는 검색어 길이·메서드·경로를 검증하고 외부 요청 대상은 두 출처로 고정한다. 공개 엔드포인트는 요청량을 제한한다. Secrets는 응답·로그에 넣지 않는다.
- Worker 무료 플랜과 NAVER API HUB의 한도를 넘으면 위키백과 결과 또는 오류로 응답한다. API HUB의 무료 제공은 한시적이므로 일별 이용 한도를 콘솔에서 설정한다.

## 공개 문서와 검증

- 확장 권한을 Worker 주소로 바꾸고, 개인정보 처리방침·README·스토어 문구의 전송처와 출처 설명을 수정한다.
- 단위 테스트: 네이버 결과, 0건, 429, 5xx, 위키백과 전환, 입력 거부, 출처 렌더링, 캐시 분리. 로컬 E2E는 Worker 응답을 가짜로 대체한다.
- 라이브 API 호출과 배포는 계정 인증 정보가 준비된 뒤 별도로 검증한다.
