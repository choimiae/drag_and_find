# 필요할 때만 영어 문맥 자료 조회

## 목표

현재 개발 브랜치에서 영어 뜻 구분 검색의 첫 결과 지연을 줄인다. 카드는 한 번만 표시하며, 주변 문맥은 브라우저 밖으로 보내지 않는다.

## 흐름

1. Worker의 `/lookup`은 네이버 백과와 한국어 위키백과 기본 결과 및 뜻 후보만 반환한다.
2. 확장 백그라운드의 조회 서비스가 브라우저 내부의 주변 문맥으로 후보를 먼저 판단한다.
3. 영어 검색어의 영어 중심 문맥에서 판단이 불확실하고 뜻 후보가 있을 때에만 Worker의 `/english-context`에 후보 문서 제목을 보낸다. 문맥, 선택한 웹페이지 주소, 검색어는 이 요청에 넣지 않는다.
4. Worker는 후보의 영어 연결 문서 도입부를 조회하여 제목별 영어 설명만 반환한다. 브라우저가 이를 원래 후보에 붙여 다시 판단하고, 최종 결과를 한 번 전달한다.
5. 추가 요청이 실패하면 기본 결과를 그대로 표시한다.

## 제약

- 추가 요청은 최대 8개 후보 제목만 받으며, 고정된 위키백과 호스트만 조회한다.
- 기존 `/lookup` 응답 형식과 한국어 검색 동작을 유지한다.
- 영어 설명을 기다리는 경우에만 추가 시간이 발생한다.
- 이 작업은 게시된 `v1.0.1`이 아닌 현재 개발 브랜치의 검색 속도 개선이다.

## 확인

- Management처럼 한국어 뜻이 문맥에 직접 언급되면 추가 요청이 없다.
- 영어 문맥에서 확신이 없으면 후보 제목만 추가 요청한다.
- 추가 요청 실패 시 기본 결과를 표시한다.
- 단위 테스트, 타입 검사, 린트 및 브라우저 빌드를 실행한다.
