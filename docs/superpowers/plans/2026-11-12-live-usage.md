# 실시간 조회 사용량 구현 계획

**목표:** 기존 조회 이벤트를 D1에 기록해 관리자 화면의 조회 완료·실패·사용 설치 수를 약 15초마다 갱신한다.

**구조:** 조회 Worker는 기존 `/telemetry` 검증 후 D1 일별 건수와 해시 설치 ID를 기록한다. 관리자 Worker는 같은 D1을 읽고 Access로 보호한 가벼운 사용량 API를 제공한다. 관리자 화면은 이 API만 주기적으로 새로고침한다.

**기술:** Cloudflare Workers, D1, TypeScript, Vitest, Playwright.

1. D1 SQL 스키마와 저장·집계 모듈의 실패 테스트를 작성한다. 건수 증가, 중복 설치 제거, 한국 날짜 경계, 1·7·30일 합계와 삭제를 검증한다.
2. 저장·집계 모듈을 구현하고 단위 테스트를 통과시킨다.
3. `/telemetry`의 D1·GA4 독립 기록 실패 테스트를 작성하고 연결한다. 기존 요청 형식과 GA4 전송을 유지한다.
4. 관리자 API에 D1 사용량 섹션과 전용 갱신 경로를 테스트 먼저 추가한다. 두 경로 모두 기존 Access 검증을 통과해야 한다.
5. 관리자 UI에서 D1 수치를 별도 출처로 표시하고, 화면이 보일 때 15초마다 갱신하는 테스트를 작성한 뒤 구현한다.
6. 개인정보 처리방침과 관리자 운영 문서를 갱신하고 포맷·린트·타입·단위·E2E 검사를 실행한다.
7. D1을 생성하고 스키마와 두 Worker 바인딩을 준비한다. 배포 승인을 받은 뒤 두 Worker를 배포하고 실제 조회 이벤트로 확인한다.
