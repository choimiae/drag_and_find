# Worker 장애 시 위키백과 직접 조회 설계

## 목적

Cloudflare Worker의 무료 요청 한도 초과, 자체 요청 제한, 배포 장애, 연결 오류 또는 시간 초과가 발생해도 사용자가 단어를 찾으면 위키백과 설명을 표시한다. 네이버 API 실패 시 Worker가 위키백과를 사용하는 기존 동작은 유지한다.

## 선택한 방식

확장 프로그램의 백그라운드에서 Worker 조회를 먼저 실행한다. Worker 조회가 `network_error` 또는 `rate_limited`로 끝나면 확장 프로그램이 위키백과를 직접 조회한다. Worker가 `found` 또는 `not_found`를 정상 반환하면 추가 조회를 하지 않는다. Worker가 HTTP 1027을 포함한 비정상 응답을 보낼 경우 기존 Worker 클라이언트가 `network_error`로 처리하므로 같은 전환 경로를 따른다.

직접 조회에는 현재 Worker가 사용하는 한국어 위키백과 조회 코드를 재사용한다. 한국어 문서를 바로 찾지 못한 영문 검색어에는 영어 위키백과의 한국어 연결 문서를 찾는 기존 경로를 적용한다. 직접 조회 결과는 `source: 'wikipedia'`이며 네이버 API나 위키데이터를 호출하지 않는다. 직접 조회도 실패하면 `rate_limited` 또는 `network_error`를 반환해 기존 오류 UI를 사용한다. 정상적으로 문서가 없는 경우에는 `not_found`를 반환한다.

브라우저의 직접 조회 요청은 `Api-User-Agent`로 앱을 식별하고, Worker의 서버 측 요청은 현재의 `User-Agent`를 유지한다. 사용자에게 선택한 검색어만 위키백과로 보내며 주변 문맥은 브라우저 안에서만 처리한다.

## 권한과 안내

`wxt.config.ts`의 호스트 권한에 `https://ko.wikipedia.org/*`와 `https://en.wikipedia.org/*`를 추가한다. 두 도메인은 각각 직접 한국어 조회와 영문 검색어의 한국어 연결 문서 조회에 필요하다. Chrome 업데이트에서 새 권한 승인 안내가 나타날 수 있으므로 스토어의 권한 설명, 개인정보 안내, README에 장애 시 직접 조회 경로를 명시한다. 다른 웹사이트 접근 권한은 추가하지 않는다.

## 구성 요소

- Worker 클라이언트는 현재처럼 HTTP, 응답 형식, 시간 초과를 `LookupResult`로 변환한다.
- 백그라운드는 Worker 조회 서비스와 직접 위키백과 조회 서비스를 따로 만든다. 전환 서비스는 Worker 결과의 실패 상태만 감지하고 직접 위키백과 조회 서비스를 실행한다. 정상 응답에는 영향을 주지 않는다.
- 두 조회 서비스는 기존 문맥별 뜻 선택을 사용한다. 직접 위키백과 조회 서비스는 장애 난 Worker의 영어 문맥 보강 경로를 다시 호출하지 않아 설명 카드가 더 지연되지 않는다.

## 검증

- Worker `found` 및 `not_found`: 직접 위키백과 요청 없음.
- Worker 네트워크 오류, 시간 초과, HTTP 429 및 1027: 위키백과 결과 표시.
- 영어 다의어를 직접 조회할 때 장애 난 Worker의 `/english-context` 호출 없음.
- 직접 위키백과 조회 실패 및 문서 없음: 기존 오류 또는 문서 없음 표시.
- 영문 검색어: 한국어 위키백과에 없는 경우 언어 연결 문서 조회.
- 배포 빌드의 manifest에 Worker와 두 위키백과 호스트 권한이 포함되는지 확인.
- 단위 테스트, 타입 검사, 빌드로 기존 조회 흐름의 회귀를 확인.

Worker 요청은 현재 최대 18초까지 기다릴 수 있으므로 장애 시 첫 결과가 늦어질 수 있다. 평상시 위키백과 요청을 늘리지 않기 위해 실패할 때만 직접 조회한다.
